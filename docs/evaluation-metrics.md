# 评估指标（Evaluation Metrics）

## 1. 指标分层体系

根据项目需求，我们将指标分为两层：**系统级指标**（Langfuse 观测）和 **质量级指标**（Ragas 评估）。

```
商业层：购买转化率 ────────────── 最终目标
                        ↑
质量层（Ragas）：Faithfulness
                Answer Relevancy
                Context Precision  ── AI 回答好不好
                        ↑
系统层（Langfuse）：响应时间
                   Token 消耗
                   调用链路          ── 系统跑得快不快
```

---

## 2. 质量评估指标（Ragas）

### 2.1 Faithfulness（忠实度）

| 项目 | 内容 |
|------|------|
| **定义** | AI 的回答是否基于检索到的商品信息，没有编造 |
| **为什么重要** | 电商场景中，编造商品信息（如虚假价格、不存在的功能）会导致用户信任崩塌 |
| **目标值** | ≥ 0.9 |
| **演示 Q&A** | "如果用户问'这款手机防水吗'，而商品信息里没有提到防水，AI 应该如实说'没有相关信息'，而不是自己编一个'支持 IP68'" |

### 2.2 Answer Relevancy（回答相关性）

| 项目 | 内容 |
|------|------|
| **定义** | AI 的回答是否与用户问题相关，没有多余或偏离的内容 |
| **为什么重要** | 用户问跑鞋，AI 回答跑鞋，而不是推荐篮球鞋或聊天气 |
| **目标值** | ≥ 0.8 |
| **演示 Q&A** | "相关性低意味着 AI 可能误解了用户意图，这会直接影响购买转化" |

### 2.3 Context Precision（上下文精确度）

| 项目 | 内容 |
|------|------|
| **定义** | 检索到的商品信息中，有多少是真正相关的 |
| **为什么重要** | 用户搜"200 元以下的跑鞋"，如果检索结果里混入了 500 元的篮球鞋，就是低精确度 |
| **目标值** | ≥ 0.8 |
| **演示 Q&A** | "这个指标衡量的是检索质量，决定了后续 LLM 生成回答的基础是否可靠" |

## 3. 系统性能指标（Langfuse 观测）

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 平均响应时间 | < 3s | 用户发送到收到回复 |
| Token 消耗/会话 | 追踪记录 | 用于成本分析 |
| LLM 调用成功率 | > 99% | API 调用是否成功 |
| 端到端追踪覆盖率 | 100% | 每次交互都被记录 |

---

## 4. 商业指标

| 指标 | 说明 |
|------|------|
| 购买转化率 | 发起购买请求的用户中，最终完成支付的比例 |
| 用户留存率 | 演示期间用户是否会多次交互 |
| 搜索成功率 | 用户发起搜索后，是否找到了想要的商品（用户行为判断） |

## 5. 工具映射

| 指标 | 工具 | 作用 |
|------|------|------|
| Faithfulness | Ragas | 评估 |
| Answer Relevancy | Ragas | 评估 |
| Context Precision | Ragas | 评估 |
| 响应时间、Token 消耗、链路追踪 | Langfuse | 观测与记录 |
| 评估结果可视化 | Langfuse | 在仪表盘中展示评估分数 |
